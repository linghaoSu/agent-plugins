# Requirements - Mandatory Brainstorm Gate

**Slug:** ITS-BRAINSTORM-MANDATORY
**Date:** 2026-05-09
**Status:** draft

## Problem

`idea-to-ship` currently documents `/brainstorm` as the first stage, but some
downstream skills can still proceed with missing or optional `requirements.md`.
That lets agents skip requirement mining and reconstruct intent from diffs,
implementation logs, or roadmap items. The user wants `/brainstorm` to be a
required stage, not an optional convenience.

## Users / Actors

- Maintainer: starts a new idea-to-ship slug and needs a concrete requirement
  artifact before design or implementation.
- Reviewing agent: checks downstream work against requirements rather than
  inferring product intent from code.
- Roadmap author: can sequence work, but must not treat roadmap planning as a
  substitute for brainstormed requirements.

## In Scope

- Make `/brainstorm` the mandatory first stage for new idea-to-ship slugs.
- Require `requirements.md` before `/architect`, `/review-design`,
  `/implement`, `/test`, and `/review-code`.
- Clarify that `/roadmap` does not replace `/brainstorm`; implementation-ready
  slug work must still have requirements.
- Add contract fixture coverage so this rule does not regress.

## Out of Scope / Non-Goals

- Adding a new file metadata schema to prove `requirements.md` was generated by
  `/brainstorm`.
- Forcing portfolio roadmap refreshes to create requirements for every
  speculative candidate before planning.
- Installing hooks or CI checks.

## Functional Requirements

1. README must state that brainstorm is mandatory for every new
   idea-to-ship slug.
2. Downstream skills must stop if `requirements.md` is missing and direct the
   user to run `/brainstorm --slug <slug>`.
3. `/test` must not use diffs, logs, or existing test plans as a replacement
   for missing requirements.
4. `/review-code` must not perform idea-to-ship review without requirements.
5. `/roadmap` must state that roadmap sequencing does not replace brainstorm.
6. Eval fixtures must check the mandatory brainstorm contract.

## Non-Functional Requirements

- **Performance:** not applicable.
- **Reliability / failure mode:** missing requirements should fail closed with
  a clear next command.
- **Platform / constraints:** Markdown skill instructions plus existing Python
  standard-library fixture script.

## Success Criteria

- `bash tests/idea-to-ship-eval-fixtures.sh` passes and includes mandatory
  brainstorm contract checks.
- `rg` no longer finds README guidance saying idea-to-ship steps can be skipped.
- `scripts/release-gate.sh --mode working` and `--mode all` pass.

## Open Questions

- None. The user explicitly chose mandatory brainstorm.

# Architecture - Mandatory Brainstorm Gate

**Slug:** ITS-BRAINSTORM-MANDATORY
**Date:** 2026-05-09
**Status:** draft
**References:** requirements.md

## Summary

Make `/brainstorm` the mandatory entry point by tightening downstream skill
input gates and documenting the roadmap boundary. The implementation is a
documentation and contract-fixture change: no runtime framework or new schema.

## Goals / Non-Goals

Goals:

- Stop downstream idea-to-ship skills when `requirements.md` is missing.
- Keep roadmap useful for portfolio sequencing without letting it replace
  brainstormed requirements.
- Add fixture checks that guard the mandatory brainstorm contract.

Non-goals:

- Proving a `requirements.md` file was generated by one exact command.
- Adding CI or hooks.
- Requiring requirements for speculative roadmap candidates before they are
  selected for work.

## Codebase Context

- `architect` already requires `requirements.md`, but still allows thin
  requirements to be patched with assumptions.
- `implement`, `test`, and `review-code` currently treat requirements as
  optional or replaceable by other artifacts.
- `roadmap` is portfolio-capable and can plan from local artifacts without a
  single feature slug.
- `tests/idea-to-ship-eval-fixtures.py` already checks critical skill
  contracts through grouped regex invariants.

## Alternatives Considered

### Option A - Hard Gates In Every Downstream Skill

Update every downstream skill to require `requirements.md`, and update roadmap
to say it does not replace brainstorm.

**Pros:** clear behavior, small blast radius, no new schema.
**Cons:** cannot prove the file came from `/brainstorm`.
**Risk:** low.

### Option B - Add Requirements Metadata

Add a frontmatter key to `requirements.md` and require downstream skills to
validate it.

**Pros:** stronger proof of origin.
**Cons:** changes artifact schema and makes old requirements files look invalid.
**Risk:** medium.

### Option C - Enforce Through Release Gate Only

Add a release-gate check that scans skills for missing brainstorm language.

**Pros:** centralized enforcement.
**Cons:** does not change agent behavior unless the skill instructions also
change.
**Risk:** medium.

## Recommendation

**We pick Option A plus a contract fixture.** It changes the behavior where
agents read it, avoids artifact schema churn, and adds enough regression
coverage to prevent the rule from silently disappearing.

## Chosen Design - Detail

### Module Breakdown

- `idea-to-ship/README.md` - describe brainstorm as mandatory and remove skip
  guidance.
- Downstream `SKILL.md` files - require `requirements.md` and point to
  `/brainstorm --slug <slug>` when missing.
- `idea-to-ship/skills/roadmap/SKILL.md` - clarify roadmap does not replace
  brainstorm for implementation-ready work.
- `tests/idea-to-ship-eval-fixtures.py` - add mandatory brainstorm contract
  checks.

### Failure Modes & Handling

- Missing requirements: downstream skill stops and prints the brainstorm command
  to run.
- Thin requirements: downstream skill sends the user back to refine
  `/brainstorm` instead of inventing product intent.
- Portfolio roadmap candidate lacks requirements: roadmap may list it as a
  candidate, but the next action is brainstorm before architecture or code.

### Test Strategy Hooks

- Contract fixture checks README and downstream skills for mandatory brainstorm
  language.
- Release gate validates skill frontmatter, JSON manifests, whitespace, and
  secrets.
